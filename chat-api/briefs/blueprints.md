## Intro

Blueprints (blueprints.naveenlabs.tech) is a library of reference architectures for AI agents. Each blueprint has its components, failure modes, threats, an evaluation plan and a monthly cost with volume sliders, and each one passes a linter. You can compare two, find the nearest one for your requirements, or ask the **Architect** agent to design a custom one from plain words.

<!-- more -->

Blueprints helps someone who must design an AI agent system choose a sound, priced architecture instead of starting from a blank page.

- **Library** (`/`): reference architectures with a why-trace, components, failure modes, threats, an evaluation plan, a flow diagram and a cost model with volume and token sliders.
- **Finder** (`/finder`): a requirements profile goes in; decision rules pick the topology and the mandatory controls and list the nearest blueprints.
- **Compare** (`/compare`): two blueprints side by side, differences highlighted.
- **Runnable starter**: a LangGraph skeleton generated by code from a blueprint, pinned and symbol-checked.
- **Lint API**: lint, decision and cost for any blueprint JSON.
- **Architect** (`/architect`): describe a system in plain words; it asks up to 4 questions, then drafts, checks, reviews and prices a design in a few minutes. Designs are private links, deleted after seven days.

## Architecture

Two containers behind a TLS proxy: **blueprints-web** (FastAPI and Jinja, read-only filesystem) serves the library and APIs and runs the Architect; **blueprints-batch** drafts new blueprints on a schedule. Data lives in SQLite (WAL); the library is published as immutable, hash-checked releases. Nothing a model writes is published until it passes the linter and the owner approves it.

<!-- more -->

- **blueprints-web**: FastAPI with Jinja, non-root, read-only filesystem. It serves the library, Finder, Compare, the lint API and the Architect agent on background threads, with a live event stream.
- **blueprints-batch**: a durable job worker (leases, cached stages, backoff, dead-letter). Nightly it drafts one blueprint from a brief; a draft goes through the linter, the decision rules and the cost model, is revised up to twice, and is either stored as rejected or waits for the owner's approval.
- **Publishing**: approved blueprints are published as an immutable release with a SHA-256 manifest; web verifies before serving; the last 10 releases are kept.
- **Living links**: with read-only access to Trust's grades and Radar's API data, components show grades, starters are symbol-checked, and a grade drop or a breaking change flags the affected blueprints for regeneration.
- **Prices** live in a pricing table with a source and a date; a table older than 45 days is flagged stale. A blueprint that fails today's linter or uses stale prices is shown with a banner, never hidden.
- **Shared agent runtime**: budget-checked model gateway with a backup model and real cost, run store, runner and event stream, shared with Trust and Radar.

## Strengths

- **Models draft, code decides**: the linter, the decision rules and the cost model are code; nothing a model writes is published until it passes them and the owner approves it.
- **Launch gate**: before the Architect was switched on it passed 8 of 8 evaluation cases at $0.024 and 166 s per design on average.
- **Tested**: 724 tests, and the library evaluation scores 1.00.

- **Code is the referee**: topology choice, mandatory controls, lint errors and cost all come from code, so two runs on the same input agree on the rules even when the wording differs.
- **Launch gate**: the Architect passed 8 of 8 cases with real models at a mean of $0.024 and 166 s per design before it went live.
- **Honest about age**: stale prices and blueprints that fail today's linter are bannered, not hidden.
- **Bounded spend**: $0.20 and 15 minutes per design, $0.25 a day, runs per visitor, a queue, a weekly brake and stop-all. Batch drafting has its own $0.03 daily cap.
- **Privacy**: in the bring-your-own-key mode the visitor's key is used only in their browser and is never sent to or stored by the site.
- **Hardened**: per-visitor limits applied before validation, a 200 KB body cap, NaN and oversized numbers refused, strict CSP, non-root read-only containers.
- **Tested**: 724 tests in CI on every push and a library evaluation at 1.00.

## Intelligence

The Architect is an agent built on a LangGraph graph. It asks up to 4 clarifying questions ranked by design impact, grounds itself in the library, lets the decision rules choose the topology, then drafts the design, a decision record, a runbook, a cheaper variant and a capacity estimate. The linter and consistency checks loop until the design is clean, and one paid review scores it and red-teams it.

<!-- more -->

- **The flow**: clarify (up to 4 questions ranked by design impact), ground in the library, choose the topology by the decision rules (code), draft the design, a decision record, a runbook, a cheaper variant and a capacity estimate, then a check-and-fix loop: lint, consistency and the latency target; the model returns only the changed parts.
- **The review**: one paid reviewer model scores 8 areas and runs a red team of up to 3 rounds; only an uncontrolled critical attack blocks the design.
- **The models**: DeepSeek drafts, records and fixes; GLM reviews at low reasoning effort; data collection is denied. A free model would run only after the visitor ticks a consent box (none is configured).
- **The output**: a priced design at a private 7-day link, with Markdown and JSON downloads.
- **Guardrails**: the budget is checked before every model call, there is a backup model, the real cost is recorded, and designs in flight are marked failed after a restart.
- **Batch generation** uses one model to draft, but every draft must pass the linter and the decision rules, and the owner approves it before it is published.
